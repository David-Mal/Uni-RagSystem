# Synthesis document template

> Authoring instructions only; this file is not a synthesis document.

## Replace with a substantive section title

Write an original English explanation of one training topic. Define its terms
and explain the evidence before the project's interpretation. Keep each
substantive section between 300 and 500 tokens. A level-two heading starts a
section; do not hide short fragments under deeper headings. Each section must be
understandable independently.

Replace the sample ID with the assigned unique ID and prefix a descriptive
filename with it, following syn01-syn05. Patrick's assignments are syn06-syn10.
Choose tags only from TAGS.md. List external citation keys in front matter and
link supported claims to their SOURCES.md entries, using keys as link text.
Do not insert placeholder citations into a synthesis. Add
`exercise_ids` only when confirmed canonical IDs are relevant; otherwise omit
that optional field. No additional mandatory front matter is required.

Separate published findings from project conventions. Research conclusions need
a source passage and limitations. Project equations and settings need a link to
the architecture plan. A study boundary is not automatically a project threshold.
Mark unsettled specifications [TO VERIFY] rather than filling gaps from memory.

Record access, version-specific licenses, human verification status and verifier
in SOURCES.md. Public access does not establish an open license. Keep human
verification pending until the person reads the original and confirms the claim.
Drafts remain outside the approved corpus until blockers and non-author review
are resolved.

Keep a draft notice before the first section while review is pending. Count
section bodies, excluding front matter, title, notice and section heading.
Estimate tokens as ceiling of body characters divided by four, including
citations and equations; this is not a model tokenizer. Recheck with the chosen
tokenizer. SOURCES.md records current estimates and outstanding checks.
